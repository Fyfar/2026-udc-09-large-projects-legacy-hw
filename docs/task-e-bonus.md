# Task E (bonus) — обрано шлях 1

## Шлях 1 — три способи навігації

**Умови експерименту**, щоб порівнювався лише спосіб навігації:
- Чотири незалежні субагенти, однакова модель (Sonnet 5), READ-ONLY. Перші три запущено паралельно, LSP — окремо, після встановлення мовного сервера.
- Код — стан після Task C (коміт `1691356`).
- Однакове питання для всіх: «Хто залежить від того, як форматує дати спільний форматер `app/lib/format.js` (`formatDate` і `formatDateUa`)? Для кожного споживача — `file:line`, як він дістається до форматера, точки входу (HTTP / cron / CLI) і хто читає вихід». Про динамічний виклик у питанні нічого не сказано.
- Відмінність лише в дозволених інструментах:
  1. **Текстовий пошук:** тільки `grep`/`rg`, без читання файлів.
  2. **Субагент Explore:** без обмежень, «як зазвичай».
  3. **ast-grep:** пошук лише структурними шаблонами; `Read` — тільки щоб підтвердити знайдене.
  4. **LSP:** лише інструмент `LSP` у Claude Code (`findReferences`, `incomingCalls`, `workspaceSymbol` тощо); `Read` — тільки для рядків, на які вказав LSP; при цьому агент мав чесно зупинитись, якщо LSP нікуди не веде.
- **Еталон для оцінки** оркестратор зафіксував **до** запуску: 3 споживачі, 4 точки входу, механізм динамічного виклику (`docs/impact.md` §2, з урахуванням переходу на `formatDateUa` у §5).
  - **Споживачі:**
    - `invoices/render.js:38-39` і `notifications/reminders.js:40,46` → `formatDateUa`, їх читає клієнт;
    - `export/accounting.js:30` → `format['format' + col.type]` з типом `"Date"` із `config/export-columns.json:3-4` → `formatDate`, його читає «Облік-Плюс».
  - **Точки входу:** `GET /invoices/:number`, `bin/render-invoice.js`, `bin/send-reminders.js`, `bin/nightly-export.js`.
- **Як з'явився LSP.** Спершу вбудований інструмент `LSP` у Claude Code відповів `No LSP server available for file type: .js`. Щоб його увімкнути, знадобилось:
  - плагін `typescript-lsp@claude-plugins-official` і глобальний `typescript-language-server` 6.0.1;
  - **TypeScript 5.x:** з глобальним TypeScript 7.0.2 сервер падав з `Could not find a valid TypeScript installation`, бо TS 7 (переписаний на Go) не має `lib/tsserver.js`. Запрацювало з `typescript@5.9.3`.

  В `app/` нічого не встановлено, `package.json` не змінено. ast-grep 0.45.3 запускався через `npx`.
- **Вартість:**
  - виклики, токени й час — з лічильника Claude Code по завершенні субагента;
  - «з кешу» — сума `cache_read` із транскрипту; за Task A відомо, що транскрипт її занижує, тож це нижня межа, придатна лише для порівняння.

Для порівняння: наївний пошук за іменем одною командою, `grep -rln formatDate lib bin server.js`, повертає лише `format.js`, `render.js` і `reminders.js`. Експорт для «Облік-Плюс» він пропускає.

**Висновок:**
- **Вирішила стратегія, а не інструмент.** Три способи з чотирьох знайшли повну відповідь, бо почали з питання «хто підключає `format.js`», а не з пошуку за іменем функції. Одна команда `grep` за іменем пропускає саме той вихід, що ламається без жодної помилки.
- **Explore — найшвидший і найдешевший:** 1.1 хв і 42k токенів, у 2 рази менше за ast-grep. Цього досить для першого проходу. Але він читає файли цілком, і в його звіті трапляються неперевірені узагальнення.
- **ast-grep — найдорожчий (4.6 хв, 82k токенів), зате єдиний дає вичерпний доказ,** що інших динамічних звертань до `format` і прихованих імпортів немає. Перед правкою контракту з іншою системою потрібен саме такий доказ.
- **Текстовий пошук — посередині,** але без читання файлів цілком він до механізму не дістався.
- **LSP — найдорожчий (6.7 хв, 110k токенів) і найменш повний.** На цьому коді він найнебезпечніший:
  - **без `jsconfig.json`** не бачить викликів через `require` з інших файлів;
  - **з `jsconfig.json`** знаходить прямі виклики `formatDateUa`, але для `formatDate` видає впевнене «0 посилань». Динамічне ім'я `format['format' + col.type]` для нього не посилання.

  «Find references» доводить наявність, але не відсутність. Єдиний споживач, якого він не бачить, — саме контракт з «Облік-Плюс».
- **Практичне правило для цього репо:**
  - першим проходом — Explore;
  - потім `ast-grep --pattern 'format[$EXPR]'` і `'$OBJ[$EXPR]'` як доказ;
  - LSP — лише для переходу з конкретного виклику до визначення, не для питання «хто залежить»;
  - головна пастка записана в `app/AGENTS.md`.
